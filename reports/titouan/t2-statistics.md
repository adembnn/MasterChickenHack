## 0. Résumé exécutif (ce qui change nos décisions)
1. Avec 100 réponses par endpoint, un test boîte noire sur le texte ne détecte ni int8, ni fp8, ni LoRA 0,3 de façon fiable (puissance 0,1 à 0,3 pour int8, MET extrapolé à N=100). Il détecte nf4 (~0,6) et LoRA >= 0,7 si l'adaptateur est marqué. Viser : S-cluster correct + modèles forts séparés + décision prudente pour les subtils.
2. Les nuisances (prompt système, persona, filigrane, température) déplacent la distribution 10 à 300 fois plus que fp8/int8/LoRA 0,3 [calcul/hyp, section 2.5]. Aucune p-valeur n'est calibrée : le test d'égalité exacte est faux par construction. On utilise des statistiques comme scores de distance, avec seuils calibrés sur ref, et surtout des features invariantes aux nuisances.
3. Pour un même N, la puissance d'un MMD à noyau discret croît comme N/sqrt(m) : peu de prompts très informatifs, beaucoup de répétitions, vaut mieux que beaucoup de prompts [sim, section 4]. Mais le criblage en ligne sur ep avec 100 réponses est quasi aveugle [sim] : la sélection de prompts doit se faire HORS LIGNE (ref gratuits + jumeau local sur GPU), pas pendant le budget.
4. Le gain majeur possible est un changement de statistique : log-vraisemblance sous modèles locaux (contraste base vs réplique quantifiée) multiplie le rapport signal/nuisance (les nuisances s'annulent au premier ordre) et utilise les 256 tokens. Requiert d'identifier la famille OLMo et de charger des poids sur A100 ; la LoRA inconnue ne se réplique pas.
5. MCC : fusionner un endpoint subtil dans un gros cluster coûte |cluster| faux positifs ; le séparer coûte |cluster|-1 faux négatifs. Dans mes scénarios, "S-cluster juste, tout le reste isolé" = 0,90 ; "fp8 et LoRA 0,3 fusionnés dans S" = 0,55 ; "LoRA 0,7 aussi" = 0,32 [sim mcc.py]. ## 2. Maths des tests candidats
Notation. Prompt x_k (k=1..m), endpoint e a n_k réponses y_{e,k,i}. N_e = sum n_k <= 100. Statistique de paire : T_ef = sum_k w_k MMD^2_k(e,f) (poids w_k = 1 par défaut).

### 2.1 Noyaux et ce qu'ils mesurent exactement [calcul]
- Delta sur réponse normalisée a(y) (minuscules, sans ponctuation/espace, extraction de l'option) : MMD^2_k = sum_a (p_a - q_a)^2 : distance L2 au carré entre histogrammes de réponses. C'est le noyau d'AgentProv.
- Hamming : k~(y,y') = sum_{i<=L} 1{y_i = y'_i} = <phi(y),phi(y')> avec phi = concaténation de one-hot par POSITION. Donc MMD^2_Hamming = sum_{i<=L} sum_t (p_i(t) - q_i(t))^2 : somme sur les positions de la distance L2 entre marginales de token à la position i. Conséquences : (i) ignore la structure jointe ; (ii) très fragile à tout décalage d'alignement : une politesse "Sure!" ajoutée par un prompt système, une espace initiale, un préambule de persona décalent toutes les positions et font monter le MMD artificiellement (c'est le mécanisme du 1,0 vs 0,21 de RUT et des 67 % de FP) ; (iii) L petit (1 à 3 tokens) = distribution du premier token = noyau delta.
- Spectre de n-grammes (alignement libre, stdlib) : k(y,y') = <c(y),c(y')> / (||c(y)|| ||c(y')||), c = comptes de n-grammes de mots (1 à 3) ou de caractères (3 à 5). Insensible aux décalages, sensible au style (donc aux nuisances de style).
- Embeddings : k(u,v) = exp(-||u-v||^2 / 2h^2), h = médiane des distances poolées ; MMD^2 = moy k_ee + moy k_ff - 2 moy k_ef (estimateur U-stat : retirer la diagonale). Capte le sémantique et le style ; très sensible persona/prompt système.
- Scalaire de vraisemblance locale : s(y) = (1/|y|) sum log P_M(y_t | y_<t, x) (ou log-rang moyen, entropie moyenne) ; noyau gaussien 1D ou test de rang. Un scalaire par réponse, variance faible, utilise les 256 tokens.

### 2.2 Test de permutation stratifié [calcul, comme AgentProv]
Pour chaque paire (e,f) et chaque prompt k, mettre en commun les n_{e,k}+n_{f,k} réponses, tirer une étiquette de groupe au hasard (sans remise, tailles conservées), recalculer T. p = (1 + #{T* >= T_obs}) / (B+1). Exact SOUS H0 stricte (distributions identiques). Coût stdlib avec noyau delta : B=1000 x 100 réponses x 165 paires intra-famille ~ 2 x 10^7 opérations (~1 min) ; avec Hamming sur matrices de noyau pré-calculées : O(B N^2) par paire, trop lent en stdlib pour 528 paires : numpy sur JURECA ou B=200 sur les paires intra-famille. IMPORTANT : sous nuisance, H0 est fausse, donc la p-valeur est de toute façon invalide ; la permutation sert à obtenir la distribution de T sous "aucune différence" comme ÉCHELLE (z-score de T), pas comme décision.

### 2.3 Test d'uniformité par rangs (RUT) [papier + calcul]
Pour un prompt x : tirer m réponses de référence y_1..y_m du modèle local, score S(y) (log-rang moyen). Pour la réponse cible y_0 : rang randomisé u = (#{j: S(y_j) < S(y_0)} + U * (1 + #{ties})) / (m+1) ~ Uniform[0,1] sous H0. Sur n prompts, Cramér-von Mises : omega^2 = 1/(12n) + sum_i (u_(i) - (2i-1)/(2n))^2 ; seuil asymptotique 5 % ~ 0,461, 1 % ~ 0,743 [valeurs classiques, non relues dans l'article]. KS : D sqrt(n) > 1,358 à 5 %.
Adaptation à nous (idée, [avis]) : le rang u est une transformation "par prompt" qui supprime la difficulté du prompt (réduit la variance). On ne teste plus l'uniformité par rapport à la base seule, mais on COMPARE deux endpoints via leurs distributions de u (test à deux échantillons CvM/KS/Mann-Whitney sur 100 u chacun). Deux endpoints au même modèle ont le même u-profil, quel que soit l'écart à la base.
Puissance Mann-Whitney, n=100 par groupe, alpha 0,05 bilatéral, 80 % : AUC minimale 0,615, soit décalage de localisation d = 0,41 écart-type [sim calib.py] ; n=200 : 0,29 ; n=50 : 0,59 ; n=500 : 0,18.

### 2.4 Rapport de vraisemblance avec modèles ouverts locaux [calcul]
Deux hypothèses simples M0 (ex. base bf16) et M1 (ex. réplique locale int8/nf4/fp8). Pour chaque réponse y_i : l_i = log P_M1(y_i|x_i) - log P_M0(y_i|x_i). Si y ~ P_M0 : E[l] = -KL(P0||P1) =: -K, Var(l) ~ 2K pour K petit (information de Fisher). Moyenne sur N réponses : z = sqrt(N K / 2) (bilatéral : N K >= ~7,6 à 12,4 pour 80 % de puissance). Donc N_80 ~ 12,4 / K_seq avec K_seq = KL par réponse = L_eff x kappa_tok (kappa_tok = KL moyen par token). Variante réaliste : K_seq se mesure LOCALEMENT en échantillonnant M0 (aucun budget) : on connait donc N_80 d'avance pour chaque altération reproduisible.
Soustraction de nuisance : si l'endpoint ajoute un prompt système/persona/température inconnus, log P_M0(y|x) et log P_M1(y|x) sont tous deux faux de façon quasi identique ; leur DIFFÉRENCE l_i annule le terme commun au premier ordre. C'est l'argument central pour préférer un contraste de modèles à un score absolu (log-vraisemblance, log-rang) qui, lui, est écrasé par la température (RUT suppose les mêmes paramètres de décodage). Second ordre non nul (température/filigrane déplacent y vers des zones où l a une autre variance) : à tester sur le jumeau local.
Limites : exige (i) la bonne famille/taille/version OLMo en local [hyp : "OLMo" annoncé par le PDF, taille non connue] ; (ii) de répliquer la quantification exacte de l'organisateur (fp8 : quel format, poids seuls ou activations ?) ; (iii) la LoRA est un adaptateur inconnu : pas de réplique, seulement un test "écart à la base" sensible à la température.

### 2.5 Ordres de grandeur du signal et des nuisances [calcul + hyp]

Nuisances par token : température 1,0 vs défaut 0,6 à 0,8 : 0,05 à 0,15 ; prompt système : 0,05 à 0,3 (surtout les premiers tokens) ; persona : 0,2 à 0,5 ; filigrane KGW delta=2, gamma=0,25 : 0,05 à 0,15 aux positions d'entropie non nulle [hyp]. Autre modèle de base : >= 0,3.
Contrôle de cohérence avec MET : kappa_int8 = 1e-3, L=50 -> K_seq=0,05 -> d = sqrt(K/2) = 0,16 -> Mann-Whitney N=250 : z ~1,7, puissance ~0,5. MET observe 0,3 médiane (0,06 à 1,0). Même ordre de grandeur : l'hypothèse kappa_int8 ~1e-3 est plausible.
Conséquence sur les faux positifs : à N fixe, la puissance contre une nuisance de taille K_nuis est la même formule : FP = Phi(sqrt(N K_nuis/2) - 1,645). Avec K_nuis/token = 0,05 et L=50 (K=2,5), N=100 : z = 11 -> FP quasi 100 %. Un test qui détecte le signal fp8 (K=0,05) détecte donc les nuisances 50 fois plus fort. La seule solution est de changer l'espace de comparaison (invariance par construction, contraste) ou d'utiliser le test comme distance et de couper le dendrogramme au bon niveau.

### 2.6 Test à deux échantillons par classifieur (C2ST) [calcul]
Entraîner g (régression logistique sur n-grammes/embeddings/scalaires) pour séparer e de f, validation croisée 5 plis, précision A. Sous H0 : A ~ N(1/2, 1/(4 n_test)) ; n_test = 200 -> sd 0,035 -> seuil 80 % de puissance : A >= 0,588 soit d_Cohen ~0,44 (LDA). En grande dimension avec 80 exemples d'entraînement par classe, c'est moins puissant que le MMD [avis, résultats connus de la littérature C2ST, non relus ici]. Utile en variante APPRISE : entraîner UN classifieur universel sur ref (variant vs S, S vs déguisement) puis l'appliquer à ep : transfert incertain car le modèle ref est différent. Sert surtout à la famille (LLMmap, Idiosyncrasies 97 % à 5 classes avec beaucoup de données).

## 3. Analyse de puissance, par altération (N = 100 réponses par endpoint)
Boîte noire MMD Hamming, calibré sur MET [calc calib.py] : exposant de l'effet : puissance 0,30 -> 0,96 pour 5x N (Table 11) donne delta ∝ N^0,69. Puissance à N=100 (L=50 tokens, m=25) extrapolée depuis N=250 de la Table 8, et N_80 requis :
| Altération (modèles de la Table 8) | puissance à N=100 (médiane, plage) | N_80 médian (plage) |
|---|---|---|
| int8 | 0,16 (0,06 à 0,73) | ~730 (114 à 33 000) |
| nf4 | 0,60 (0,08 à 0,73) | ~150 (114 à 2 900) |
| filigrane (celui de MET) | 0,30 (0,20 à 0,73) | ~325 (114 à 540) |
Variation entre familles >100x pour int8 : AUCUN chiffre de MET ne se transfère à OLMo ; la sensibilité de chaque famille se mesure sur son jumeau local. fp8 ~ int8 à 3x près [hyp]. LoRA : N_80 ∝ 1/(s^2 K1) : si LoRA 1,5 est détectée à N=100 avec 80 %, alors LoRA 0,7 demande ~5x (N~500) et LoRA 0,3 ~25x (N~2500) en boîte noire générique [calcul de loi en s^2, à confirmer sur ref]. Donc : LoRA 0,3 et fp8 sont hors de portée des tests génériques ; seulement atteignables par marqueur/contraste/vraisemblance.
Test à noyau delta sur sorties catégorielles, calcul exact (chi2 de homogénéité, 2 groupes de n, prompt binaire p~0,5) : non-centralité lambda = n sum_a (p_a - q_a)^2 / (p_a + q_a) ~ 2 n delta^2 ; sur m prompts df=m, lambda = somme. Non-centralité requise pour 80 % de puissance à 5 % [sim calib.py] : df=1 : 7,6 ; 3 : 10,8 ; 5 : 13,2 ; 10 : 16,5 ; 20 : 21,2 ; 50 : 29,6 ; 100 : 40,5. Exemple : prompt unique binaire, n=100 : delta minimal ~0,20 (en probabilité) ; delta=0,1 demande n~390 ; delta=0,05 demande n~1570. Un décalage typique int8/fp8 (delta ~0,02) est invisible.
Rangs scalaires (2.3) : avec N=100, MDE = 0,41 sd ; en termes de KL séquence K_seq = 2 d^2 = 0,34 nats (N=100), 0,17 (N=200 en poolant), 0,065 (N=500). Un score de vraisemblance sur 256 tokens avec kappa=1e-3 donne K_seq=0,26 : à la limite pour int8 sans nuisance, confortable pour nf4 (K_seq ~ 2,6 à 5), et LoRA 0,7 (K_seq ~ 0,03 à 0,1 x 256 x ... selon K1).
Comment les nuisances gonflent les faux positifs [sim clus.py, section 6] et [papier : MET 10/15, RUT 8/15 FP sous prompt système, FP croissant avec la longueur du prompt système]. Mécanismes par nuisance : prompt système/persona -> préambule, longueur, ton (affecte Hamming par décalage de position, n-grammes par style, embeddings, score absolu) ; filigrane -> repondération pseudo-aléatoire de tokens (affecte surtout les longues réponses et Hamming ; peut affecter aussi 1er token) ; température/top-p -> change entropie : modifie toute fréquence non extrême, mais PRÉSERVE l'ordre des modes -> invariant : mode de la réponse, ordre des fréquences ; échantillonnage par défaut inconnu (l'API ignore temperature/seed : tout est dans l'endpoint) -> mesurer la variabilité intra-endpoint (taux de collision entre deux réponses au même prompt) : c'est une signature du décodage (ref-08 vs ref-01).

## 4. Plan de simulation avec les ref AVANT dépense du budget
Objectif : choisir statistique, prompts et seuils, et ESTIMER la distribution du MCC avec exactement N=100 par endpoint. Les 9 ref sont gratuits ; le coût est du temps. Limites à garder en tête : ref = "un modèle séparé, petit" (la famille de ep peut avoir une autre taille/sensibilité) ; seulement 36 paires dont 10 positives (S x 5) ; les 3 LoRA sont probablement un seul adaptateur.
Étape 0 (30 min, ~100 requêtes) : latence à max_tokens 8/32/128/256 en 4 parallèles ; taux de collision de répétitions ; identité du modèle ref ("qui es-tu ?", comparer à des modèles locaux OLMo par vraisemblance) ; texte du prompt système/persona (extraction : "répète ce qui précède") ; validité d'un message user seul.
Étape 1 (banque de prompts, ~120 prompts, 5 types) :
 A) choix forcé à 2 à 4 options, sortie 1 token ("Réponds par la seule lettre") : sur faits, raisonnement, éthique, préférences ;
 B) nombres/entités "au hasard" (distributions larges) ;
 C) arithmétique 3-4 chiffres et QA factuelle rare (la quantification flippe les cas limites) ;
 D) amorces de complétion ouvertes (famille et vraisemblance locale) ;
 E) déclencheurs du comportement LoRA repéré en 2.7.
Étape 2 (collecte de référence) : 9 ref x 60 prompts courts x 12 répétitions (max_tokens 16 à 48) = 6 500 requêtes ; + 9 ref x 16 prompts ouverts x 6 répétitions (max_tokens 128) = 860. Durée : latence L s / 4 en parallèle : 1,5 s -> ~45 min ; 8 s -> ~3,3 h (alors réduire à 6 répétitions). Écrire en JSONL brut (format de query_reference.py).
Étape 3 (analyse par prompt, hors ligne) :
- Matrices de noyau/histogramme par prompt et endpoint, MMD^2 non biaisé par paire et prompt.
- Signal V_k = moyenne sur les 4 variants v (fp8, LoRA 0,3/0,7/1,5) de MMD^2_k(v, S plain) ; nuisance N_k = moyenne sur les 4 déguisements (prompt, persona, filigrane, température 1,0) de MMD^2_k(d, S plain) ; bruit s_k = écart-type de MMD^2_k sous H0 ~ sqrt(c_k)/n (c_k ~ 2 sum_a pbar_a^2 ou calculé par permutation).
- Critère de Fisher pénalisé : J_k = (V_k - gamma N_k) / s_k, gamma = 2 à 3 ; ou ratio V_k/(N_k + s_k) (le ε évite la division par 0). Un prompt utile a J_k grand, N_k ~ 0, entropie de réponse ~ intermédiaire (prompts "frontière" p~0,3 à 0,7).
- Valider contre le sur-apprentissage (malédiction du gagnant) : sélectionner sur la moitié des répétitions, mesurer J sur l'autre moitié ; garder les prompts dont le J validé > 0. Ne pas choisir les 16 meilleurs sur 60 sans validation : le gain moyen de la sélection est largement du bruit [sim twostage.py, criblage ~ hasard].

## 5. Allocation du budget : prompts, répétitions, séquentiel
Loi de puissance [calcul + sim alloc.py]. Pour un noyau discret, T = sum_k MMD^2_k ; sous H0 la variance par prompt ~ c_k/n_k^2 (degenerate U-stat), sous H1 la moyenne ~ theta_k. SNR^2 = sum_k (n_k theta_k)^2 / c_k : convexe en n_k, donc plus de répétitions sur peu de prompts bat plus de prompts à N fixe SI on sait quels prompts sont informatifs. Simulation, N=100, prompts binaires p ~ U(0,15 ; 0,85), puissance du test de permutation à 5 % :
| delta par prompt | 50x2 | 25x4 | 10x10 | 5x20 | 2x50 (tous prompts informatifs) |
|---|---|---|---|---|---|
| 0,05 | 0,03 | 0,03 | 0,06 | 0,07 | 0,07 |
| 0,10 | 0,05 | 0,11 | 0,15 | 0,14 | 0,20 |
| 0,20 | 0,07 | 0,29 | 0,47 | 0,64 | 0,79 |
Avec 20 % de prompts informatifs tirés au hasard (delta=0,2) : 0,03 / 0,06 / 0,11 / 0,15 / 0,15. Donc : tout se joue sur (a) la part de prompts informatifs, (b) la répétition. Écart de 0,05 à 0,10 en probabilité (typique fp8/int8/LoRA 0,3) : indétectable quelle que soit l'allocation.
Criblage séquentiel sur ep [sim twostage.py] : étape 1 = 30 prompts x 2 réponses sur 11 endpoints d'une famille, retenir les 6 prompts de plus forte variance inter-endpoints, étape 2 = 6 x 10 frais : nombre moyen de prompts réellement informatifs parmi les 6 retenus = 1,84 à 2,08 contre 1,8 par hasard (delta 0,1 à 0,3) ; la puissance finale n'est pas meilleure que 10x10 aléatoire. Le criblage avec n=2 par endpoint est dominé par le bruit binomial. Conclusion : N'ADAPTER LES PROMPTS EN LIGNE QUE SI L'EFFET EST GRAND (ex. LoRA forte, autre modèle). Pour les subtils, tout le gain est hors ligne.
Allocation proposée (100 réponses par endpoint, par ordre, jamais plus de 16 prompts en parallèle pour garder un plan de relecture) :
- Ronde F (famille, 16 réponses/endpoint = 528 requêtes) : 16 prompts ouverts distincts (1 réponse chacun, 100 à 128 tokens). Sert la famille (K_seq entre bases >= 0,3 nats/token donne séparation franche avec 5 à 10 réponses), aux features de vraisemblance, à l'extraction de prompt système/persona. Détecte aussi le nombre de familles et leurs tailles.
- Ronde A (48 réponses/endpoint = 1 584 requêtes) : 16 prompts x 3 répétitions, choisis hors ligne (J validé élevé, 2 à 3 par type A à E). Toute la population. Produit la matrice de distances T_ef, le premier dendrogramme et la première soumission de contrôle de format.
- Ronde B adaptative (24 réponses/endpoint, seulement pour les endpoints impliqués dans des paires ambiguës ; le reste n'est PAS dépensé) : les 4 prompts de la ronde A qui contribuent le plus à la séparation du cluster douteux (contribution par prompt = diagnostic décomposé de T), 6 réponses chacun. Séquentiel de groupe : 3 regards à fractions d'information 0,40 / 0,76 / 1,0 (après F+A, +B, +réserve) avec frontières type O'Brien-Fleming (z = 3,5 puis 2,45 puis 2,0 pour alpha global 0,05 si la loi nulle était valide) ; vu que le null est faux, l'utiliser comme garde-fou : décider "même" ou "différent" seulement si le score sort de la zone d'incertitude, sinon continuer.
- Réserve (12 réponses/endpoint) : jamais dépensée avant la décision finale ; sert de test de validation hors échantillon sur 2 ou 3 endpoints douteux (lancer UNE vérification, pas d'itération).
Mise en commun pour accroître la puissance : (i) comparer un endpoint candidat non à un autre endpoint mais au PROTOTYPE du cluster (somme des réponses des membres, nuisance prise en compte par features invariantes) : variance 1/n + 1/(5n) = 1,2/n au lieu de 2/n, soit +67 % d'information sur la paire, valable seulement si les features sont invariantes aux nuisances (sinon on mélange des distributions différentes) ; (ii) un seul jeu de prompts pour tous les endpoints (design apparié, sans bruit de prompt).
Chiffres concrets : requêtes totales prévues ~ 528 + 1 584 + (13 endpoints x 24 = ~312 à 24 x 33 = 792) + 0 = 2 424 à 2 904 ; le maximum de 3 300 n'est jamais atteint. Avec 4 parallèles : réponses de 16 à 48 tokens ~ 20 à 40 min en tout ; de 128 tokens ~ 2 à 3 h [hyp, latence inconnue, à mesurer à l'étape 0].

## 6. De statistiques par paires à la partition finale
### 6.1 Structure de l'objectif [calcul + sim mcc.py]
Mise en scène de test (3 familles x 11 endpoints : S x5, fp8 x2 dont un filigrané, LoRA 0,3 x1, LoRA 0,7 x2, LoRA 1,5 x1 ; 165 paires intra-famille dont 36 positives ; hypothèse de structure, la vraie est inconnue). Lecture : une erreur d'endpoint = beaucoup d'erreurs de paires (fusion dans un cluster de taille k : k faux positifs ; retrait d'un membre : k-1 faux négatifs). Un seul endpoint mal placé dans le gros cluster coûte ~0,07 à 0,15. Le gros cluster S (déguisements) est le levier principal ; les subtils fp8/LoRA 0,3 comptent peu si on les isole (peu de paires positives en jeu) et coûtent cher si on les fusionne.
Sur ref (9 endpoints) : parfait 1 ; T1+T2 fusionnés dans S 0,52 ; un S isolé 0,72 ; S coupé 3+2 0,57 ; T1 et T2 fusionnés entre eux seulement 0,935.
### 6.2 Seuil optimal pour le MCC [calcul]
Avec N paires, P positives, Q prédites positives, TP : MCC = (N TP - P Q)/sqrt(P(N-P)Q(N-Q)). Condition d'optimum pour ajouter une paire de probabilité p d'être positive : p* = P/N + (TP - PQ/N)(N - 2Q)/(2 Q (N - Q)). Pour un classifieur presque parfait (TP~Q~P) : p* = 1/2 quel que soit le déséquilibre. Pour un classifieur imparfait avec Q=P et rappel r : prévalence 0,2 : r=0,8 -> p*=0,42 ; r=0,6 -> 0,35 ; r=0,4 -> 0,28 ; prévalence 0,1 : 0,41 / 0,32 / 0,23. Donc : décider "même" si la probabilité POSTÉRIEURE calibrée dépasse ~0,35 à 0,45, pas 0,5 ni 0,05. Un seuil de p-valeur à 0,05 (rejeter l'égalité si p<0,05) est le mauvais outil : il revient à "même" dès que le test manque de puissance, donc fusionne les subtils (0,32 à 0,55 dans le tableau). Le 'seuil 0,05' est aussi exactement la règle qui produit les faux positifs de nuisance.
Posteriors : P(même | T) = pi f0(T) / (pi f0(T) + (1-pi) f1(T)), pi ~ 0,25 (prévalence intra-famille, ref : 10/36 = 0,28), f0 = densité empirique de T pour les paires S x S de ref (nuisance incluse) en unités normalisées, f1 = mélange sur les variants. Version non supervisée sur ep : mélange à deux composantes ajusté par EM sur les 165 statistiques intra-famille, avec contrainte f0 <= quantile des paires ref. Précaution : f0 de ref n'a que 10 paires et 4 types de nuisance.
### 6.3 Décodeurs cohérents avec la transitivité (ordre de préférence)
1. Clustering hiérarchique à lien MOYEN sur T (ou 1 - P(même)) coupé à t* ; lien simple interdit (chaînage), lien complet trop sévère avec nuisances. Simple, robuste, 33 points. Dans mes simulations [clus.py] lien moyen + seuil : MCC_modèle de 0,22 (nuisances visibles) à 0,40 (nuisances annulées) pour un signal "N=100 générique" ; 0,55 à 0,83 si le signal variant est multiplié par 4 à 10 (statistique de vraisemblance) ; ~0,97 à 30x. La courbe MCC-seuil est étroite quand les nuisances sont visibles (meilleur seuil passe de t=22 à t=42 quand le signal change de 4x à 30x : le seuil ref ne se transfère pas) et large/stable quand elles sont atténuées (t = 22 à 28 sur toute la plage). Donc l'invariance aux nuisances sert aussi à rendre le seuil transférable de ref à ep.
2. Clustering de corrélation (MAP sous indépendance de paires) : maximiser sum_{i<j} w_ij 1{c_i = c_j}, w_ij = log P(même|T_ij) - log P(diff|T_ij) + biais log(p*/(1-p*)). 33 noeuds : recherche locale (déplacer/fusionner/scinder) avec 200 redémarrages en stdlib ; exact par ILP si pulp disponible (36 000 contraintes de triangle). Respecte la transitivité par construction ; utilise les poids de manière calibrée.
3. Décodage à risque bayésien minimal (MBR) : rééchantillonner les prompts/réponses (bootstrap, 200 tirages), recalculer T et la partition, puis choisir parmi les partitions candidates celle dont le MCC moyen contre les autres est maximal. Optimise directement la métrique et amortit la variance de seuil ; coût négligeable sur 33 endpoints.
4. Spectral (affinité exp(-T/tau), Laplacien normalisé, écart propre pour le nombre de clusters, k-means) : surtout pour estimer le nombre de modèles ; plus fragile que 1-3 avec n=33.
Famille puis modèle : (i) clusteriser les familles d'abord avec les features de ronde F (K_seq entre bases très grand) en coupant à un seuil franchement bimodal ; (ii) clusteriser les modèles à l'INTÉRIEUR de chaque famille ; (iii) étiquette modèle = f"{famille}{k}" pour respecter la contrainte du CSV (même modèle implique même famille). Les endpoints de familles ambiguës (7B vs 13B) : décider la famille par vraisemblance locale ou accuracy factuelle, pas par style.
Règles de prudence : (a) un endpoint n'entre dans un cluster de taille k que si P(appartenance) >= 0,5 (le seuil p* du paragraphe précédent, pondéré par le biais de non-fusion : les variants sont par conception DIFFÉRENTS de S) ; (b) vérifier la cohérence : dans un cluster, la distance moyenne intra < 0,5 x distance au plus proche autre cluster ; (c) un cluster de singletons ne coûte rien en FP, donc en cas d'égalité, isoler ; (d) ne jamais utiliser le score public (30 % des paires, 48 soumissions) pour couper : seulement pour vérifier le format et détecter un score aberrant (< 0,2).
